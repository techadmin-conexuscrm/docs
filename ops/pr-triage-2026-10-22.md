## Open security holes confirmed on current main

1. **Offer update can point at another company's payment gateway.** Open.
   - Where: `src/components/campaigns/services/update-offer.ts:16-23` writes `...data` (including `gatewayInstanceId`) with no organization check. The charge then loads the gateway by id alone: `src/components/transactions/services/create-transactions-for-order.ts:69-71` (`inArray(gateways.id, gatewayIds)`, no org filter).
   - Scenario: an admin of company A sends `PUT /v1/offers/<A's offer>` with `{gatewayInstanceId: <B's gateway uuid>}`. A's next orders on that offer are charged through company B's merchant account.
   - Fix: #290 (update half).
2. **API-key events skip every background listener.** Not a leak, but an integrity gap.
   - Where: `src/components/events/index.ts:62/71` queues the api_keys id as `userId`; `src/components/events/job.ts:30` throws loading it.
   - Scenario: an order created through the API never fires the tenant's outbound webhooks, activity or plugin handlers.
   - #284 fixes it by running those listeners as the system user, which needs Eric's decision.
