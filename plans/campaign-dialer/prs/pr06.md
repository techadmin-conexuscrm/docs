# Calling-hours records and report, live-lead intake sweep, My campaigns, retry sequences

**Base:** `claude/campaign-pr05-state-calling-rules` · **Migration:** `0116` · **Merge order:** 6 of 14

## Problem
- Changes to the state rules must be auditable: who reviewed each rule, and every change.
- A lead refused for the time of day must be rescheduled, not dropped, and the hold must be reportable.
- New orders must become campaign leads.
- Each agent chooses which of their campaigns they are taking calls for.
- Admins design the retry sequences.

## Root cause
None of this existed.

## Fix
- **Migration 0116:**
  - adds `state_calling_rule_changes`, written by a trigger on every rule update;
  - adds `dialer_calling_hours_holds`;
  - adds the review columns on `state_calling_rules`, with a CHECK that "reviewed" has a date.
- **CR-2:** admins read the rules and their own narrowing. Only super admins record a review.
- **CR-3 / CR-4:**
  - a lead refused for the time of day is held and rescheduled;
  - the "Held for calling hours" report has search and CSV export (formula-escaped), scoped to the company.
- **BE-5a intake sweep:** each order is decided once. Supersede never closes the lead made from the same or a later order.
- **BE-4c "My campaigns":** per agent and per campaign, off until the agent says so.
- **BE-4d retry sequences:** one default per company. A delete falls back safely.
- **The dialer's routes are dark** while the platform switch is off (decision of 21 Oct).

## Why this is safe
- All routes are behind `CAMPAIGN_DIALER_ENABLED`, and the sweep job does not start while it is off.
- The migration creates new tables, and alters only `state_calling_rules`, which was created in PR-05 in the same deploy.
- Ships in **Deploy 2** (PR-02…PR-14 together, one restart). See the deploy plan.
