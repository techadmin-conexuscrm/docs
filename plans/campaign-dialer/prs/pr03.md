# Internal do-not-call list, disposition categories, and enforcement for campaign calls

**Base:** `claude/campaign-pr02-dialer-settings` · **Migration:** `0113` · **Merge order:** 3 of 14

## Problem
Each company needs its own do-not-call list:
- "please don't call me again" must stick;
- the campaign dialer must never ring a number on it;
- admins need to search it, add and remove numbers, and export it.

This replaces **#371** (same feature, rebased, migration renumbered 0113, with the review fixes). #371 should be closed as superseded.

## Root cause
There was no internal list. Dispositions such as "Do not call" or "Wrong number" were just labels, with no effect.

## Fix
- **Migration 0113:**
  - adds `do_not_call_numbers`, with one active row per company and phone;
  - adds `call_dispositions.category` (nullable, CHECK-limited);
  - backfills the category for dispositions already named "do not call" or "wrong number".
- **Admin API** `/v1/do-not-call/:organizationId`:
  - search, add, remove and CSV export;
  - the export uses `Papa.unparse(…, { escapeFormulae: true })` and is built after the transaction;
  - numbers added by hand are rate-limited and capped.
- Choosing a categorised disposition adds the number.
  - Only the person's own request ("do not call") crosses companies of the same call centre.
  - A "wrong number" never crosses companies.
- **Enforcement:** campaign and preview calls always check the list. Agents' own dials (click-to-call and softphone) are checked only for companies listed in `INTERNAL_DNC_ENFORCE_MANUAL_ORGS`, which is empty by default.

## Why this is safe
- Manual dialling is unchanged unless `INTERNAL_DNC_ENFORCE_MANUAL_ORGS` names the company. That setting is empty in production.
- Every query is scoped to the organization:
  - an API key is recorded as no person, and adds and removes are logged by id;
  - no phone numbers go into logs;
  - no I/O happens inside a transaction.
- **Migration:**
  - it touches one existing table, `call_dispositions`, with a nullable column, a CHECK and two small `UPDATE`s;
  - the table is small, and `lock_timeout` is 10 s;
  - everything else in it is a new table.
- Ships in **Deploy 2** (PR-02…PR-14 together, one restart). See the deploy plan.
