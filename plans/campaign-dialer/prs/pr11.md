# Campaign audio and a company default voicemail (BE-2); journal-order guard

**Base:** `claude/campaign-pr10-abandon-wrap-up-monitor` · **Migration:** `0121` · **Merge order:** 11 of 14

## Problem
- Each campaign needs its voicemail and "no agent free" recordings.
- A company needs a default voicemail for one-click drops.
- Intake must start at the moment the company switched campaign dialing on, not at the last time its settings were saved.

## Root cause
- No audio settings existed.
- Intake read `updated_at`, which every settings save moves.

## Fix
- **Migration 0121** adds `campaign_dialing_enabled_at`, backfilled from `updated_at`, and `default_voicemail_file_id` on `dialer_campaign_company_settings`.
- **`campaign-audio.ts`:**
  - the file must be audio, at most 30 s, and the company's own;
  - a replacement file must still fit every dialer use;
  - signed playback links last 5 minutes.
- `switches.ts` sets `campaignDialingEnabledAt` only on off→on.
- **Guard test** `migration-journal.test.ts`: journal `when` values must strictly increase. Drizzle decides what to apply by these dates, so an out-of-order date silently skips a migration.

## Why this is safe
- Everything is behind `CAMPAIGN_DIALER_ENABLED`.
- The migration adds columns to a table created in this same deploy.
- Ships in **Deploy 2** (PR-02…PR-14 together, one restart). See the deploy plan.
