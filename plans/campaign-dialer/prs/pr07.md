# Callback schedules per company; live-lead intake listeners

**Base:** `claude/campaign-pr06-calling-hours` · **Migration:** `0117` · **Merge order:** 7 of 14

## Problem
- Each company designs its own pattern for calling back people it never reached.
- New orders should reach the dialer quickly, without waiting for the sweep.

## Root cause
The per-campaign cap and back-off columns in 0112 were too rigid for the approved design.

## Fix
- **Migration 0117** adds `dialer_callback_schedules`, with one default per company and an optional schedule per campaign, and `dialer_callback_schedule_changes` as their log.
- **This PR also edits 0112**, which has not run anywhere yet:
  - it removes `pool_max_attempts`, `pool_max_age_days` and the four `backoff_*` columns, with their CHECKs;
  - the schedules replace them.
- **BE-5b intake listeners:** the fast path, hand-off only. None are registered while the switch is off.

## Why this is safe
- The listeners and routes are behind `CAMPAIGN_DIALER_ENABLED`.
- **This PR edits an earlier migration in the same stack, so PR-02 and PR-07 must ship in the same deploy.** If 0112 ran on its own first, production would keep the removed columns forever. The deploy plan keeps them together.
- Ships in **Deploy 2** (PR-02…PR-14 together, one restart). See the deploy plan.
