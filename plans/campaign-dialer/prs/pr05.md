# State calling rules, auto-dial guards, call timing and campaign scripts

**Base:** `claude/campaign-pr04-campaign-dialing-schema` · **Migration:** `0115` · **Merge order:** 5 of 14

## Problem
- A campaign may only ring a lead inside the hours that lead's state allows, never on banned holidays, and within the attempt caps.
- The dialer also needs, at the moment it dials:
  - one call per customer;
  - no ringing an agent who is busy;
  - no premium-rate or other costly numbers;
  - a record of ring, answer and bridge times for every attempt.
- Agents on a campaign call need that campaign's script.

This replaces **#374** (state rules, renumbered 0115). #374 should be closed as superseded.

## Root cause
- No state rules existed.
- The originate path had no campaign-specific guards.
- The call-end handler kept no per-attempt timing.

## Fix
- **Migration 0115** adds `state_calling_rules`, seeded with 56 rows. Where sources disagree, the stricter reading wins, and each rule carries its lawyer-review status.
- `components/calling-rules/`:
  - the lead's local time, from state and area code (zone and state disagreeing → both sets apply);
  - holidays;
  - the calling window, with a buffer of at least 2 minutes.
- **The auto-dial cap** counts both the customer and the number. A stored cap of 0 can't crash it.
- **Originate:**
  - its options are set server-side only;
  - one dial per customer;
  - busy and live-call guards;
  - the state rules are re-checked at the moment of dialing.
- `dialable-gate.ts`: auto-dial never rings premium, shared-cost, personal, UAN, pager, voicemail or non-US/CA NANP numbers, whatever `DIALABLE_NUMBERS_MODE` says.
- **Call timing (BE-6a):** `notify.ts` records the leg's timing on the attempt via `recordDialerLegEvent`. It returns before any query when campaign dialing is off, and it never fails the settle.
- **Campaign scripts (BE-11):**
  - a campaign call gets its campaign's script and `{{campaign.name}}`;
  - only the agent on the call records the script version shown.

## Why this is safe
- Every new path runs only for campaign calls, and campaign calls cannot exist while the switches are off.
- In `notify.ts`, the timing hook is a no-op when campaign dialing is off. It sits before the existing queue logic, which is unchanged. This PR merged `main`'s new queue-abandon handling alongside it.
- Manual calls go through the same originate and destination code. The new guards apply only to the campaign origin.
- The migration creates one table and seeds it.
- Ships in **Deploy 2** (PR-02…PR-14 together, one restart). See the deploy plan.
