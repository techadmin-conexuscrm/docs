# Campaign dialer: campaigns, their settings and the on/off switches (nothing dials)

**Base:** `claude/campaign-pr01-calls-cap-indexes` · **Migration:** `0112` · **Merge order:** 2 of 14

## Problem
The campaign dialer needs somewhere to keep each campaign, its settings and the agents on it. It also needs layered switches so it can never dial by accident:
- a platform switch;
- a per-company switch;
- a super-admin "pause everything".

This replaces **#372** (same feature, rebased onto the stack, with its migration renumbered 0112 and its review fixes). #372 should be closed as superseded.

## Root cause
None of this existed.

## Fix
- **Migration 0112** adds `dialer_campaigns`, `dialer_campaign_agents`, `dialer_campaign_company_settings` and `dialer_platform_controls`. The platform controls table is seeded with one row, "paused everywhere = false".
- The campaigns API lives under `/v1/dialer-campaigns`, with services in `components/dialer-campaigns/`.
- **Switches:**
  - `CAMPAIGN_DIALER_ENABLED` (env, default off). It is parsed so that only true/1/yes/on mean on; a typo never boots the API "on".
  - Each company has its own "Campaign dialing" switch, off. The call centre's admins may turn it on.
  - Super admins have a "pause everything" that takes effect at once. A missing platform row reads as paused.
- `dialingBlockers()` is the single "may this campaign dial now" check the pacer uses later.
- Every stored setting is clamped when it is read.

## Why this is safe
- Every new route is mounted only when `CAMPAIGN_DIALER_ENABLED` is on. Off, they answer 404 (see `dialerCampaignRoutesFor`).
- Nothing in this PR places a call.
- Permissions are checked in the services:
  - API keys can read and pause, never switch on the riskier settings;
  - everything is scoped to the organization;
  - turning a company off takes its locks in the documented order.
- The migration only creates new tables and seeds one row.
- **PR-07 edits this migration** (it removes the per-campaign cap and back-off columns before 0112 has run anywhere). So this PR must ship in the same deploy as PR-07. Ships in **Deploy 2** (PR-02…PR-14 together, one restart). See the deploy plan.
